작성 기준: 2026년 10월 14일

1. 프로그램 소개와 기본 용어

SHM VIEWER는 두 가지 종류의 데이터를 보여줍니다.

  RealTime Viewer
    실행 중인 다른 프로그램이 만든 공유 메모리의 값을 조회합니다.
    헤더 파일에 정의된 구조체를 바탕으로 데이터를 해석합니다.
    이 화면은 읽기 전용이며 공유 메모리의 값을 수정하지 않습니다.

  DAT Diff
    디스크에 저장된 DAT 파일을 조회하거나 두 파일을 비교합니다.
    값을 직접 고치거나 한쪽의 값과 구조를 다른 쪽에 적용할 수 있습니다.
    편집은 먼저 앱 안의 작업본에 반영되며, 저장해야 디스크 파일이 바뀝니다.

기본 용어

  SHM 또는 공유 메모리
    여러 프로그램이 함께 접근할 수 있는 메모리 영역입니다.
    조회할 공유 메모리는 대상 프로그램이 먼저 만들어 두어야 합니다.

  SHM Name
    대상 프로그램이 공유 메모리를 만들 때 사용한 정확한 이름입니다.
    실행 파일 이름이나 DAT 파일 경로를 입력하는 칸이 아닙니다.

  헤더 파일
    C/C++의 .h 또는 .hpp 파일입니다.
    데이터가 어떤 멤버와 타입으로 구성되는지 정의합니다.

  Struct
    데이터 전체를 나타내는 최상위 구조체의 이름입니다.
    예를 들어 struct tagRun의 데이터를 보려면 tagRun을 입력합니다.
    헤더 파일 이름을 입력하는 칸이 아닙니다.

  멤버와 경로
    구조체 안에 있는 개별 항목과 그 위치입니다.
    settings.speed는 settings 안의 speed 항목을 뜻합니다.
    items[0].value는 items 배열의 첫 번째 요소 안의 value를 뜻합니다.

  타입과 크기
    int, double, 다른 구조체 등 데이터를 해석하는 형식과 바이트 수입니다.
    바이트 배치가 맞아야 값도 올바르게 해석됩니다.

  오프셋
    데이터 시작 지점에서 해당 항목까지의 바이트 거리입니다.
    +8은 시작 지점보다 8바이트 뒤에 항목이 있다는 뜻입니다.

  버전1과 버전2
    DAT 비교 화면의 왼쪽과 오른쪽 작업본입니다.
    파일의 최신·이전 버전을 자동으로 판별하는 이름이 아닙니다.
    어느 파일을 어느 쪽에 놓을지는 사용자가 정합니다.

  구조 파일
    저장된 DAT의 현재 구조와 검증 정보를 담은 .schema.json 파일입니다.
    DAT 옆에 함께 두면 변경된 구조를 다시 열 때 자동으로 사용합니다.


2. 실행 준비와 화면 구성

2.1 실행 준비

  1) 배포 압축 파일을 원하는 폴더에 풀어 둡니다.
  2) Windows x64용 .NET 8 Desktop Runtime이 설치되어 있는지 확인합니다.
     프로그램 실행만 하는 경우 개발용 .NET SDK는 필요하지 않습니다.
  3) ShmViewer.exe를 실행합니다.
  4) 실시간 조회를 하려면 공유 메모리를 만드는 대상 프로그램도 실행합니다.
     DAT 파일 조회와 비교에는 대상 프로그램이 실행 중일 필요가 없습니다.

설정 파일은 ShmViewer.exe 옆에 저장됩니다.
설정을 유지하려면 이 폴더에 파일을 쓸 수 있어야 합니다.
DAT를 저장하려면 해당 DAT가 있는 폴더에도 쓰기 권한이 있어야 합니다.

2.2 화면 구성

상단의 RealTime Viewer와 DAT Diff 탭으로 작업 화면을 바꿉니다.

  RealTime Viewer
    - Use SCTC: 실시간 조회용 기본 헤더와 SHM 탭을 설정합니다.
    - 헤더 파일 영역: 헤더 추가, 삭제, 다시 분석을 수행합니다.
    - 검색 영역: 멤버 이름과 타입을 검색합니다.
    - SHM Name / Struct / Refresh / Load: 조회할 SHM 탭을 등록합니다.
    - SHM 탭 영역: 등록한 공유 메모리별 트리와 Run / Stop을 표시합니다.
    - 검색 결과 영역: 검색된 경로를 탭별로 보여줍니다.

  DAT Diff
    - Run Data / Init Data: SCTC DAT 프리셋 종류를 선택합니다.
    - Load Only: 한 파일만 조회하는 모드로 바꿉니다.
    - 버전1 / 버전2 입력 영역: DAT와 헤더 및 Struct를 각각 설정합니다.
    - 도구 영역: 로드, 비교 옵션, 차이 이동, 편집 이력 등을 조작합니다.
    - 결과 영역: 한 파일의 트리 또는 좌우 비교 트리를 보여줍니다.
    - 고급 편집: 비교 모드에서 직접 입력, 0 적용, 삭제를 수행합니다.
    - 하단 상태 영역: 로드·편집·저장 결과와 오류를 보여줍니다.

상단 탭을 바꿔도 진행 중인 DAT 작업은 유지됩니다.
RealTime Viewer의 헤더와 DAT Diff의 양쪽 헤더는 각각 별도 설정입니다.


3. 빠르게 시작하기

3.1 공유 메모리의 현재 값 보기

  1) RealTime Viewer를 선택합니다.
  2) + 파일 추가로 필요한 헤더를 등록하고 분석 완료를 기다립니다.
  3) SHM Name에 대상 프로그램의 공유 메모리 이름을 입력합니다.
  4) Struct에 그 메모리에 대응하는 구조체 이름을 입력합니다.
  5) Refresh에서 갱신 주기를 고른 뒤 Load를 누릅니다.
  6) 만들어진 SHM 탭에서 Total Size가 대상 데이터 크기와 맞는지 확인합니다.
  7) Run을 누르면 실제 공유 메모리를 읽고 값이 표시됩니다.
  8) TYPE 옆의 펼침 버튼으로 하위 멤버를 확인합니다.
  9) 조회를 멈추려면 Stop을 누릅니다.

Load는 구조를 준비하고 탭을 만드는 단계입니다.
실제 SHM 연결과 값 읽기는 Run을 눌러야 시작됩니다.

3.2 DAT 파일 하나 열기

  1) DAT Diff를 선택하고 Load Only를 체크합니다.
  2) 조회 대상에서 버전1 또는 버전2를 선택합니다.
  3) 선택한 쪽의 DAT… 버튼으로 파일을 지정합니다.
  4) DAT 옆에 구조 파일이 없으면 + 헤더와 Struct도 지정합니다.
  5) Load를 누릅니다.
  6) 트리를 펼쳐 값을 확인합니다. 조회만 했다면 파일은 바뀌지 않습니다.

3.3 DAT 두 파일 비교하고 한 항목 적용하기

  1) DAT Diff에서 Load Only를 해제합니다.
  2) 버전1과 버전2에 서로 비교할 DAT를 각각 지정합니다.
  3) 구조 파일이 없는 쪽에는 그 DAT와 맞는 헤더와 Struct를 지정합니다.
  4) Load / 비교를 누릅니다.
  5) 차이점만 보기를 켜서 다른 항목을 찾습니다.
  6) 원하는 행의 →를 누르면 버전1 내용이 버전2 작업본에 반영됩니다.
     ←를 누르면 버전2 내용이 버전1 작업본에 반영됩니다.
  7) 결과를 확인한 뒤 변경한 쪽의 버전1 저장 또는 버전2 저장을 누릅니다.

처음 저장을 연습할 때는 DAT를 별도 작업 폴더에 복사해서 사용하세요.
저장 버튼은 지정된 원본 DAT 경로를 갱신하며 저장 전 파일을 자동 백업합니다.


4. RealTime Viewer 헤더 등록과 SHM 연결

4.1 헤더 등록과 관리

+ 파일 추가로 .h / .hpp 파일을 여러 개 선택할 수 있습니다.
RealTime Viewer에 헤더 파일을 드래그해서 놓아도 등록됩니다.
등록된 헤더는 하나의 풀로 분석하므로 최상위 구조체의 헤더뿐 아니라
그 안에서 참조하는 구조체와 enum 등의 정의도 함께 준비합니다.

  - 같은 경로의 헤더는 중복 등록하지 않습니다.
  - 헤더 목록은 폴더별로 묶어서 표시합니다.
  - 파일 위에 마우스를 올리면 전체 경로와 오류를 확인할 수 있습니다.
  - 개별 항목의 ✕로 그 헤더만 목록에서 제거할 수 있습니다.
  - Ctrl을 누르고 클릭하면 여러 파일을 개별 선택합니다.
  - Shift를 누르고 클릭하면 연속 범위를 선택합니다.
  - 선택 삭제 또는 Delete로 선택한 헤더를 한 번에 제거합니다.
  - 전체 삭제는 등록된 헤더 목록을 모두 비웁니다.

여기서 삭제는 앱의 등록 목록에서 제거하는 동작입니다.
디스크의 헤더 파일을 지우는 동작이 아닙니다.

헤더를 추가하거나 제거하면 다시 분석합니다.
헤더 내용을 외부 편집기로 수정했거나 누락 파일을 준비했다면
헤더 영역의 🔄 Refresh를 눌러 현재 파일을 다시 읽습니다.
파일이 누락되어도 등록된 경로는 목록에 유지됩니다.

분석 중에는 진행 표시와 현재 단계가 나타납니다.
헤더 분석뿐 아니라 탭의 구조체 트리와 검색 준비가 끝날 때까지 기다립니다.
Run 중인 SHM 탭이 있으면 헤더 추가·삭제·Refresh가 제한됩니다.
헤더를 바꾸려면 실행 중인 모든 SHM 탭을 Stop으로 중지하세요.

4.2 SHM 탭 등록

SHM Name과 Struct를 입력하고 갱신 주기를 선택한 뒤 Load를 누릅니다.
SHM 이름과 구조체의 조합은 대상 프로그램의 개발 정보에서 확인합니다.

예시
  SHM Name: DYNAMIC_CONFIGURE_MEMORY
  Struct:   tagDynCfg
  Refresh:  1s

이 예시는 SCTC 기본 항목 중 하나입니다.
직접 사용하는 프로그램에 해당 SHM이 있을 때만 연결할 수 있습니다.

같은 SHM 이름의 탭이 이미 있으면 Load는 기존 탭을 선택합니다.
다른 Struct나 갱신 주기로 새로 등록하려면 기존 탭의 ✕로 닫은 뒤 등록합니다.
서로 다른 SHM은 반복해서 Load하여 여러 탭으로 사용할 수 있습니다.

4.3 Run과 Stop 및 갱신 주기

  Load
    헤더의 구조체로 트리를 준비하고 SHM 탭을 등록합니다.
    대상 프로그램이 아직 실행 중이 아니어도 구조를 준비할 수 있습니다.

  Run
    SHM을 읽어 현재 값을 표시하고 선택한 주기의 갱신을 시작합니다.
    연결할 SHM이 없거나 읽기 권한이 부족하면 상태 영역에 오류가 나옵니다.

  Stop
    그 탭의 갱신을 중지합니다. 트리와 마지막 표시 값은 남습니다.
    화면에 남은 값은 이후의 실시간 값이 아닙니다.
    다시 Run하면 값을 읽고 갱신을 재개합니다.

  SHM 탭의 ✕
    갱신을 중지하고 탭을 닫습니다. 저장되는 탭 목록에서도 제거됩니다.

갱신 주기는 탭을 Load할 때 선택합니다.
  500ms: 약 0.5초마다 갱신합니다.
  1s:    약 1초마다 갱신합니다.
  5s:    약 5초마다 갱신합니다.
  수동:  Run 때 한 번 읽고, 이후 탭의 Refresh를 누를 때 읽습니다.

자동 갱신은 현재 선택된 SHM 탭에 집중합니다.
다른 SHM 탭을 보려면 탭을 선택하고 다음 갱신을 기다립니다.
각 탭의 마지막 갱신 시각으로 화면 값이 언제 읽혔는지 확인할 수 있습니다.

4.4 두 가지 Refresh 구분

  헤더 목록 옆의 🔄 Refresh
    헤더를 다시 분석하고 트리와 검색 정보를 다시 준비합니다.
    사용 전 실행 중인 모든 SHM 탭을 Stop으로 중지해야 합니다.

  SHM 탭 안의 Refresh
    수동 갱신 모드에서 공유 메모리의 현재 값을 한 번 읽습니다.
    먼저 해당 탭에서 Run을 실행한 상태여야 합니다.
    헤더 구조를 다시 분석하는 버튼이 아닙니다.


5. RealTime Viewer 트리 읽기와 검색

5.1 트리와 컬럼

트리의 최상단은 지정한 구조체이고 그 아래에 멤버가 표시됩니다.
중첩 구조체와 배열은 TYPE 영역의 펼침 버튼으로 열고 닫습니다.
큰 배열은 펼칠 때 하위 항목을 준비하므로 잠시 로딩 표시가 나올 수 있습니다.

  SIZE (+offset): 항목의 바이트 크기와 데이터 시작 기준 위치입니다.
  TYPE:          int, char 배열, enum, 구조체 등 데이터의 형식입니다.
  NAME:          멤버 이름 또는 배열 인덱스입니다.
  VALUE:         마지막으로 읽은 바이트를 해석한 값입니다.

컬럼 사이의 경계를 드래그하면 표시 폭을 조절할 수 있습니다.
하위 항목이 길거나 많으면 스크롤하여 확인합니다.
행을 클릭하면 해당 행이 선택됩니다.

  - 배열 인덱스는 0부터 시작합니다. [0]은 첫 번째 요소입니다.
  - 다차원 배열은 단계별로 펼쳐서 확인합니다.
  - enum은 정의된 이름과 숫자를 연결해서 보여줍니다.
  - union은 같은 메모리 영역을 여러 타입으로 해석한 항목을 보여줍니다.
  - 비트필드는 지정된 비트 범위의 값을 보여줍니다.
  - 포인터는 주소값을 보여주며 주소가 가리키는 메모리를 따라가지 않습니다.
  - spare, reserved, dummy와 같은 예비 필드는 회색으로 표시합니다.
  - Run 전의 빈 값이나 Stop 후의 값으로 현재 동작 상태를 판단하지 마세요.

5.2 복사와 바이너리 확인

TYPE 또는 NAME의 글자 위에서 우클릭하면 복사하기를 사용할 수 있습니다.
해당 셀에 표시된 텍스트가 클립보드로 복사됩니다.

일반 값 항목의 VALUE 위에서 우클릭하고 바이너리 확인을 선택하면
상세 팝업에서 이름, 타입, 크기, 오프셋과 다음 표현을 확인할 수 있습니다.

  DEC: 10진수
  HEX: 16진수
  BIN: 2진수
  OCT: 8진수

enum 값이면 정의된 이름 목록과 현재값 표시도 나타납니다.
구조체 그룹에는 일반 값 항목과 같은 바이너리 메뉴가 제공되지 않습니다.

현재 SHM의 바이너리 확인은 해당 탭이 Run 중일 때 사용하세요.
팝업은 열 때 데이터를 다시 읽으며 자동 갱신되는 창이 아닙니다.
Stop 상태에서는 현재 SHM을 읽지 않아 숫자 영역에 0이 표시될 수 있으므로,
화면에 남아 있는 마지막 값의 바이너리 표현으로 해석하면 안 됩니다.

5.3 이름과 타입 검색

  1) 상단 검색 입력칸에 찾을 단어를 입력합니다.
  2) 검색 범위를 전체 탭 또는 특정 SHM 탭으로 선택합니다.
  3) 검색을 누르거나 입력칸에서 Enter를 누릅니다.
  4) 하단 검색 결과에서 원하는 행을 더블클릭합니다.
  5) 해당 SHM 탭으로 이동하고 필요한 상위 항목을 펼쳐 그 행을 선택합니다.

검색은 멤버 이름과 타입에 대한 부분 일치이며 영문 대소문자를 구분하지 않습니다.
예를 들어 speed 또는 tagSensor처럼 입력합니다.
값의 숫자나 문자열을 찾는 검색은 제공하지 않습니다.
DAT Diff에는 이 RealTime Viewer 검색이 적용되지 않습니다.

아직 펼치지 않은 중첩 멤버도 검색할 수 있습니다.
배열 안의 구조체 멤버 경로에는 [n]이 표시될 수 있습니다.
[n]은 배열 요소를 대표하는 검색 경로이며 모든 인덱스가 각각 검색되었다는 뜻은
아닙니다. 결과로 이동한 뒤 배열을 펼쳐 필요한 실제 인덱스를 확인하세요.
검색 결과의 VALUE가 비어 있어도 트리의 값 조회와는 별개입니다.
현재 값은 이동한 트리에서 확인합니다.

검색 결과는 탭별로 묶여 있고 그룹을 펼치거나 접을 수 있습니다.
검색어를 지우고 다시 검색하면 결과를 비울 수 있습니다.

5.4 미발견 타입 확인

구조체 안에서 참조하는 타입의 정의가 없으면 트리 생성에 실패할 수 있습니다.
탭의 자세히 보기 또는 헤더 영역의 미발견 타입 보기에서 누락 목록을 확인합니다.
어떤 멤버가 어떤 타입을 필요로 하는지 확인한 뒤 해당 헤더를 추가하고
헤더 영역의 Refresh로 다시 분석합니다.
버튼은 확인할 누락 정보가 있을 때 표시됩니다.


6. SCTC 기본 설정과 설정 복원

6.1 RealTime Viewer의 Use SCTC

Use SCTC를 체크하면 SCTC용 헤더 7개와 SHM 탭 5개를 준비합니다.
기존 실시간 설정이 있으면 초기화하고 교체할지 확인하는 창이 나옵니다.

기본 헤더 위치와 파일
  D:\K12_SCTC\SCTCApplication\lib\internal\common\h
    _DynCfg.h, _enumdef.h, _Recipe.h, _Run.h, _StcCfg.h, k12initial.h
  D:\K12_SCTC\SCTCApplication\src\SMA\SharedMemory_App
    SharedMemory_App.h

기본 SHM Name / Struct
  RUNNING_SHARED_MEMORY       / tagRun
  STATIC_CONFIGURE_MEMORY     / tagStcCfg
  DYNAMIC_CONFIGURE_MEMORY    / tagDynCfg
  INITIAL_SHARED_MEMORY      / tagUnitInitial
  MAINTITEM_SHARED_MEMORY     / stMaintItem

기본 갱신 주기는 1s이며 자동으로 Run하지 않습니다.
필요한 탭을 선택한 뒤 각각 Run을 눌러 연결합니다.
jobinfo.h와 OBJECT_INFO_MEMORY / STJOBINFO는 현재 기본 목록에 포함되지 않습니다.

Use SCTC는 경로를 입력해 주는 기능이며 파일이나 공유 메모리를 생성하지 않습니다.
지정된 경로에 파일이 없으면 목록에 누락 상태로 남습니다.
파일을 준비한 뒤 Refresh를 누르거나 실제 환경의 헤더를 직접 등록하세요.

체크 해제에 동의하면 RealTime Viewer의 헤더, SHM 탭, 검색과 컬럼 폭을
초기화하고 실행 중인 SHM 조회를 중지합니다. DAT Diff 작업은 유지됩니다.

6.2 실시간 설정 저장과 복원

헤더 경로와 SHM 탭 설정, Use SCTC 선택은 실행 파일 옆의
realtime_settings.json에 자동 저장됩니다.
다시 실행하면 등록 경로와 탭을 복원하고 헤더 분석을 준비합니다.
복원된 탭은 정지 상태이므로 값을 읽으려면 Run을 눌러야 합니다.

새 설정 파일이 없으면 이전 header_paths.json과 shm_tabs.json을 읽습니다.
누락된 헤더 경로도 유지하므로 파일을 준비한 뒤 다시 분석할 수 있습니다.
설정 복원은 헤더나 DAT 자체를 복원하는 백업 기능이 아닙니다.
DAT Diff의 입력 설정과 미저장 작업은 앱 종료 후 자동 복원되지 않습니다.


7. DAT 입력 설정과 SCTC 경로

7.1 각 버전의 입력

DAT Diff의 왼쪽은 버전1, 오른쪽은 버전2입니다.
비교 모드에서는 양쪽을 설정하고 Load Only에서는 조회 대상 쪽만 설정합니다.

  DAT…
    조회하거나 비교할 DAT 파일을 선택합니다. 경로를 직접 입력해도 됩니다.

  + 헤더
    해당 DAT를 기록한 구조체가 정의된 .h / .hpp 파일을 추가합니다.
    다른 버전의 파일은 각 버전에 맞는 헤더를 따로 지정할 수 있습니다.

  삭제
    선택한 헤더를 등록 목록에서 제거합니다. 실제 파일은 삭제하지 않습니다.
    Ctrl/Shift 다중 선택 후 삭제 또는 Delete도 사용할 수 있습니다.

  ↑ / ↓
    헤더 하나를 선택하여 include 순서를 바꿉니다.
    목록 위에서부터 읽으므로 필요한 타입이나 enum 정의를 앞에 놓습니다.

  Struct
    DAT 전체에 대응하는 최상위 구조체 이름을 입력합니다.

DAT 또는 헤더를 해당 버전의 입력 영역으로 드래그해서 놓을 수도 있습니다.
파일이 없거나 읽을 수 없으면 헤더 목록 또는 하단 상태에 오류가 표시됩니다.

7.2 구조 파일을 자동으로 사용하는 규칙

예를 들어 DAT 경로가 sample.dat이면 앱은 같은 폴더에서
sample.dat.schema.json을 찾습니다.

  - 구조 파일이 있으면 해당 파일의 구조를 사용합니다.
    기존 헤더·Struct·파싱 옵션 입력은 이 로드에 사용하지 않습니다.
    DAT 경로만 지정해도 됩니다.
  - 구조 파일이 없으면 등록한 헤더, Struct, 파싱 옵션을 사용합니다.
  - 구조 파일이 손상되었거나 DAT와 맞지 않으면 오류를 표시합니다.
    이런 경우 헤더로 조용히 대체하지 않습니다.

DAT에 맞는 헤더를 명시적으로 사용하려면
헤더 사용 (자동 구조 파일 대신)을 체크하고 헤더와 Struct를 지정합니다.
이 선택은 올바른 헤더를 갖고 있을 때 사용합니다.
구조 변경 전의 헤더로 수정된 DAT를 열면 실패하거나 잘못 해석할 수 있습니다.

7.3 파싱 옵션

파싱 옵션 · Windows x64를 펼치면 각 버전의 분석 조건을 지정할 수 있습니다.
헤더로 로드할 때 적용되며 양쪽 버전에 서로 다른 조건을 설정할 수 있습니다.

  기본 Pack
    기본값은 8이며 1, 2, 4, 8, 16 중 하나를 입력합니다.
    구조체 멤버를 배치할 때의 기본 정렬 제한입니다.
    대상 C/C++ 프로그램의 컴파일 조건에 맞게 설정합니다.
    헤더의 #pragma pack 지정도 배치에 반영됩니다.
    파일 크기를 맞추기 위해 임의로 변경하지 말고 실제 조건을 확인하세요.

  추가 include 경로
    헤더가 다른 파일을 #include할 때 찾을 폴더를 줄마다 하나씩 입력합니다.
    예: C:\Project\include

  매크로
    NAME 또는 NAME=VALUE 형식으로 줄마다 하나씩 입력합니다.
    예: FEATURE_ENABLED
        MAX_ITEMS=16
    대상 프로그램의 조건부 컴파일과 배열 길이에 영향을 줄 수 있습니다.

헤더로 로드할 때 DAT 크기는 선택한 Struct의 바이너리 크기와 정확히 같아야 합니다.
크기 오류가 나면 DAT 버전, Struct, 헤더, Pack과 매크로 조건을 확인하세요.

7.4 DAT Diff의 Use SCTC Path

DAT Diff는 처음에 Run Data, 양쪽 Use SCTC Path 해제, Pack 8, ASCII로 시작합니다.
Run Data / Init Data는 Use SCTC Path를 켠 쪽의 프리셋 종류를 정합니다.
임의로 지정한 파일이 Run Data인지 Init Data인지 자동 판별하는 기능이 아닙니다.

  Run Data 프리셋
    헤더: _enumdef.h, _Run.h
    DAT:  D:\K12_SCTC\Resource\CTC\MEM_RUNDATA.DAT
    Struct: tagRun

  Init Data 프리셋
    헤더: _enumdef.h, k12initial.h
    DAT:  D:\K12_SCTC\Resource\CTC\INIT_UNIT.DAT
    Struct: tagUnitInitial

헤더의 기본 위치는 6.1절에 나온 폴더와 같습니다.
각 버전의 Use SCTC Path를 체크한 쪽에만 기본 경로·헤더·Struct가 입력됩니다.
Run Data / Init Data를 바꾸면 체크한 쪽의 프리셋이 다시 적용됩니다.
Pack, include 경로, 매크로 등 파싱 옵션은 그대로 유지됩니다.

DAT 경로·헤더·Struct를 직접 바꾸면 그쪽 Use SCTC Path 체크가 해제됩니다.
체크 해제 자체는 이미 입력된 경로를 지우는 동작이 아닙니다.
양쪽에서 같은 기본 DAT를 지정하면 같은 디스크 파일을 비교하게 되므로,
서로 다른 버전을 비교하려면 각 버전의 실제 파일을 따로 지정하세요.

RealTime Viewer의 Use SCTC와 DAT Diff의 Use SCTC Path는 별도 기능입니다.
한쪽을 체크한다고 다른 화면의 설정까지 바뀌지 않습니다.


8. DAT 파일 하나 조회하기

  1) Load Only를 체크합니다.
  2) 조회 대상에서 버전1 또는 버전2를 고릅니다.
  3) 해당 버전의 DAT와 필요한 구조 정보를 설정합니다.
  4) Load를 누릅니다.
  5) 이름 / 경로 앞의 펼침 버튼으로 하위 항목을 확인합니다.

컬럼 표시 ▾에서 이름 / 경로, 타입, 오프셋, 크기, 값의 표시를 조절합니다.
오프셋은 기본으로 숨겨져 있습니다.
문자 인코딩과 HEX로 표시 방법을 바꿀 수 있습니다.

Load Only에서도 값 셀 더블클릭 또는 F2로 값을 편집할 수 있습니다.
이 모드의 편집은 구조, 배열 길이, DAT 크기를 유지합니다.
구조 변경이나 두 버전 간 적용이 필요하면 비교 모드를 사용하세요.

실행 취소 / 다시 실행을 지원합니다.
변경한 작업본을 저장하려면 DAT 저장 · 원본 백업을 누릅니다.
조회만 하거나 표시 옵션만 바꾼 경우 디스크 DAT를 자동 수정하지 않습니다.


9. DAT 두 파일 비교하기

9.1 비교 결과 읽기

Load Only를 해제하고 양쪽 입력을 설정한 뒤 Load / 비교를 누릅니다.
왼쪽 버전1과 오른쪽 버전2의 구조와 값이 중앙 적용 버튼을 기준으로 표시됩니다.
버전1은 오른쪽 정렬되고 트리가 중앙에서 왼쪽으로 뻗습니다.
버전2는 중앙에서 오른쪽으로 뻗으며 숫자와 문자열의 읽기 순서는 동일합니다.

각 항목에서 경로, 타입, 크기, 배치 정보와 값을 확인합니다.
중앙에는 차이 상태와 ← / → 버튼이 있습니다.
그룹을 펼치거나 접으면 양쪽 트리가 함께 움직입니다.
깊거나 긴 경로는 가로 스크롤로 확인합니다.

비교는 이름과 멤버 경로를 기준으로 자동 대응합니다.
이름을 바꾼 멤버는 같은 항목으로 자동 연결되지 않을 수 있습니다.
수동으로 경로를 연결하는 기능은 제공하지 않습니다.

9.2 표시 옵션

  둘 다 해제
    양쪽 데이터의 전체 구조와 값을 표시합니다.

  구조 비교
    멤버의 유무, 타입, 크기, 배열 길이, 배치 등 구조 차이와
    그 차이를 찾아가는 데 필요한 상위 그룹을 표시합니다.
    구조가 같고 값만 다른 항목은 강조하지 않습니다.

  차이점만 보기
    구조 또는 값이 다른 항목과 필요한 상위 그룹을 표시합니다.

구조 비교와 차이점만 보기는 동시에 켜지지 않습니다.
다른 옵션을 켜면 기존 옵션이 해제되고, 켜진 옵션을 다시 누르면 전체 보기로 돌아갑니다.

9.3 적용 후 목록이 남아 있는 이유

같은 표시 옵션에서 적용하거나 직접 편집하면 값과 차이 상태는 즉시 바뀝니다.
같아진 행도 현재 목록에 남아 있어 작업 위치를 잃지 않고 계속 편집할 수 있습니다.
새 차이가 생기면 현재 목록에 추가됩니다.
실행 취소, 다시 실행과 저장도 이 목록을 유지합니다.

양쪽에서 모두 삭제된 경로는 현재 구조에 없음으로 표시됩니다.
이 행은 이전 작업 위치를 보여주는 것이며 값 편집이나 좌우 적용을 할 수 없습니다.
현재 작업을 실행 취소하여 항목이 복원되면 다시 조작할 수 있습니다.

이전 차이 / 다음 차이와 차이 개수는 현재 남아 있는 차이만 대상으로 합니다.
목록에 남은 동일 항목이나 현재 구조에 없음 항목은 남은 차이로 세지 않습니다.
구조 비교 모드에서는 구조 차이만 차이 이동 대상으로 삼습니다.
마지막 차이 다음에는 처음으로, 첫 차이 이전에는 마지막으로 이동합니다.

현재 데이터 기준으로 목록을 다시 구성하려면 표시 옵션을 바꾸거나 다시 로드합니다.
옵션 변경 시 미저장 작업과 실행 취소 이력의 처리는 13.1절을 먼저 확인하세요.


10. DAT 양방향 적용과 구조 변경

10.1 적용 방향

  →: 버전1의 현재 내용을 버전2 작업본에 적용합니다.
  ←: 버전2의 현재 내용을 버전1 작업본에 적용합니다.

중앙 행의 화살표는 해당 행에 적용합니다.
여러 행을 적용하려면 Ctrl로 개별 선택하거나 Shift로 연속 범위를 선택한 뒤
도구 영역의 버전1을 버전2에 적용 → 또는 ← 버전2를 버전1에 적용을 누릅니다.

적용 기준은 처음 디스크에서 읽은 데이터가 아니라 현재 편집된 작업본입니다.
예를 들어 버전1 값을 10에서 25로 직접 고친 뒤 →를 누르면 버전2도 25가 됩니다.
적용은 작업본만 바꾸며 해당 버전을 저장해야 디스크에 반영됩니다.

10.2 항목 유무에 따른 결과

  양쪽에 같은 항목이 있는 경우
    소스 쪽의 현재 내용으로 대상 항목을 바꿉니다.
    예: 왼쪽 speed=10, 오른쪽 speed=20에서 →를 누르면 오른쪽도 10입니다.

  소스에만 항목이 있는 경우
    대상에 그 항목을 추가합니다.
    예: 왼쪽에만 legacy가 있을 때 →를 누르면 오른쪽에 legacy가 추가됩니다.

  소스에 항목이 없고 대상에만 있는 경우
    대상 항목을 삭제합니다.
    예: 왼쪽에만 legacy가 있을 때 ←를 누르면 왼쪽 legacy가 삭제됩니다.
    오른쪽의 '없음' 상태를 왼쪽에 적용한 결과입니다.

화살표는 항상 값을 복사하는 버튼이라고 생각하면 안 됩니다.
한쪽이 비어 있는 행에서는 추가 또는 삭제가 될 수 있으므로 적용 전에 방향을 확인하세요.

10.3 개별 멤버와 그룹 전체 적용

  개별 멤버
    선택한 멤버를 바꾸고 형제 멤버는 유지합니다.
    일반 멤버를 추가할 때는 소스의 가까운 공통 멤버 위치를 기준으로 삽입합니다.
    대상 부모의 pack과 정렬 조건을 유지하면서 크기와 오프셋을 다시 계산합니다.

  구조체 또는 배열 그룹
    그 그룹의 멤버 구성, 선언 순서, 타입, 값과 배열 길이를 소스에 맞춥니다.
    대상에만 있던 하위 멤버는 삭제되며 소스 그룹의 배치를 채택합니다.

  루트 그룹
    전체 구조체를 대상으로 적용합니다. 대상의 전체 구조와 값이 바뀔 수 있습니다.
    단일 값만 고치려면 루트 대신 해당 하위 멤버를 선택합니다.

일부 멤버만 적용해도 정렬과 크기 재계산 때문에 뒤쪽 항목의 오프셋이 달라질 수 있습니다.
구조 변경 후 상단의 바이트 크기와 하단의 차이 상태를 확인하세요.

10.4 배열과 union의 적용 범위

배열 내부의 값만 바꿀 수 있으면 요소나 하위 멤버를 개별 적용합니다.
배열 요소는 동일한 타입을 유지해야 합니다.
타입·배열 길이·union 공유 영역 때문에 그룹 전체 교체가 필요한 경우
영향을 받는 그룹 경로를 보여주고 전체 범위 적용 여부를 확인합니다.
동의하면 안내된 범위의 구조와 모든 값을 적용하며 취소하면 변경하지 않습니다.

배열은 현재 인덱스 경로로 대응합니다.
요소를 삭제하면 뒤쪽 인덱스가 앞으로 이동하고 연속 번호로 다시 매겨집니다.
삭제 후 items[1]은 삭제 전 items[1]과 같은 데이터를 의미하지 않을 수 있습니다.

union은 여러 멤버가 같은 바이트를 공유합니다.
한 해석의 값을 고치면 다른 해석의 값도 바뀔 수 있습니다.


11. DAT 값 직접 편집과 실행 취소

11.1 값 셀 편집

  1) 고칠 버전의 값 셀을 더블클릭하거나 셀을 선택하고 F2를 누릅니다.
  2) 새 값을 입력합니다.
  3) Enter 또는 셀 입력 적용을 누르면 작업본에 반영합니다.
     다른 셀로 이동할 때도 입력을 적용·검증합니다.
  4) Esc 또는 입력 취소를 누르면 해당 입력을 취소합니다.

값이 범위를 벗어나거나 형식이 틀리면 오류가 표시되고 적용되지 않습니다.
오류를 고치거나 입력을 취소한 뒤 다음 작업을 수행하세요.
비교 모드에서는 실제로 편집을 시작한 셀의 버전에 값이 반영됩니다.
양쪽에서 모두 없어진 행이나 직접 값을 입력할 수 없는 그룹은 편집할 수 없습니다.

11.2 입력 형식

  정수:           123, -10
  16진수 정수:    0x7B
  실수:           3.14
  bool:           true, false, 1, 0
  enum:           헤더에 정의된 enum 이름 또는 해당 숫자
  문자열:         "hello"
  원시 바이트:    hex:00112233

입력 예시는 대상 타입에 맞게 사용해야 합니다.
hex:00112233은 00, 11, 22, 33의 네 바이트를 뜻합니다.
원시 바이트 입력은 대상 항목의 바이트 크기와 정확히 같아야 합니다.
비트필드는 원시 바이트 대신 정수로 입력합니다.
비교 모드의 union 그룹은 hex: 형식으로 공유 영역 전체를 편집할 수 있습니다.
정수와 비트필드는 타입의 범위를 벗어나면 거부합니다.
문자열은 배열의 바이트 용량 안에 들어가야 합니다.
입력 후 남은 공간은 0으로 채웁니다. 용량을 전부 채우면 끝을 나타내는
NUL이 들어가지 않으므로 대상 프로그램이 NUL 종료 문자열을 기대한다면
char 배열은 1바이트, wchar 배열은 2바이트의 여유를 남기세요.

문자 인코딩에서 ASCII / CP949 / UTF-8을 선택할 수 있습니다.
기존 파일을 기록한 인코딩에 맞춰야 문자열을 올바르게 읽고 쓸 수 있습니다.
ASCII로 표현할 수 없는 한글을 입력하면 적용되지 않습니다.
wchar 배열은 UTF-16LE를 사용합니다.

문자 인코딩이나 HEX 선택은 표시 방법과 이후 입력 해석에 영향을 줍니다.
옵션만 바꾸어도 기존 DAT 문자열이 다른 인코딩으로 자동 변환되는 것은 아닙니다.

11.3 고급 편집

비교 화면 아래의 고급 편집을 펼치면 다음 기능을 사용할 수 있습니다.

  편집 대상 버전1 / 버전2
    직접 입력, 0 적용, 선택 항목 삭제가 어느 작업본에 적용될지 정합니다.
    작업 전에 표시된 편집 대상 버전을 확인합니다.

  직접 입력과 적용
    선택한 항목의 새 값을 입력하고 적용을 눌러 작업본에 반영합니다.
    입력 취소는 아직 적용하지 않은 입력을 버리고 현재값으로 돌아갑니다.

  0 적용
    선택한 대상 항목의 데이터 바이트를 0으로 만듭니다.
    항목 자체를 삭제하지 않습니다. 문자열은 빈 문자열로 해석될 수 있습니다.

  선택 항목 삭제
    선택한 대상 멤버나 삭제 가능한 배열 요소를 구조에서 제거합니다.
    크기와 오프셋이 재계산되며 DAT 크기가 바뀔 수 있습니다.
    루트나 삭제할 수 없는 항목은 조작이 제한되거나 오류가 표시됩니다.

다른 항목이나 편집 대상 버전으로 이동할 때 적용하지 않은 입력이 있으면
입력을 버릴지 확인하거나 셀 입력을 검증합니다.
저장 버튼이 비활성 상태라면 먼저 남아 있는 입력을 적용하거나 취소하세요.

11.4 실행 취소와 다시 실행

실행 취소는 마지막 편집 작업을 되돌리고 다시 실행은 되돌린 작업을 복원합니다.
직접 값 편집, 좌우 적용과 구조 변경을 포함합니다.
비교 모드에서는 양쪽 버전의 작업을 수행한 시간순으로 되돌립니다.

저장해도 편집 이력은 지워지지 않습니다.
저장 후 실행 취소하면 디스크 파일은 그대로이며 작업본만 과거 상태로 돌아갑니다.
현재 저장 상태와 다르면 다시 미저장으로 표시됩니다.
되돌린 상태를 디스크에 반영하려면 해당 버전을 다시 저장해야 합니다.

다시 로드하거나 표시 옵션 전환에 성공하면 이전 편집 이력은 초기화됩니다.
문자 입력칸 안에서 Ctrl+Z / Ctrl+Y를 누르면 입력창의 편집 동작을 유지합니다.


12. DAT 저장과 백업 및 다시 열기

12.1 저장할 버전 선택

비교 모드의 버전1 저장은 버전1만, 버전2 저장은 버전2만 저장합니다.
다른 쪽에 변경 내용이 있으면 그쪽은 미저장 상태로 남습니다.
Load Only의 DAT 저장 · 원본 백업은 현재 조회 대상 파일을 저장합니다.

이 앱은 저장 시 지정된 DAT 원본 경로를 갱신합니다.
다른 이름으로 저장하는 파일 선택 창은 나오지 않습니다.
별도 결과가 필요하면 작업 시작 전에 DAT와 구조 파일을 다른 폴더로 복사하고
복사한 DAT를 로드해서 작업하세요.

12.2 저장 시 생성되는 파일

원본 파일이 sample.dat인 경우

  현재 DAT:       sample.dat
  현재 구조 파일: sample.dat.schema.json
  DAT 백업 예시:  sample_20261014_153000_123.dat
  구조 파일 백업: sample_20261014_153000_123.dat.schema.json

백업은 저장 직전 디스크에 있던 파일입니다.
기존 구조 파일이 있으면 그것도 같은 백업 이름에 맞춰 보관합니다.
첫 저장처럼 기존 구조 파일이 없던 경우에는 DAT만 백업합니다.
백업 이름이 겹치면 순번을 붙여 이전 백업을 덮어쓰지 않습니다.

저장한 DAT에 맞는 현재 구조 파일은 자동으로 생성됩니다.
원본 C/C++ 헤더는 수정하지 않으며 새 헤더도 생성하지 않습니다.

12.3 저장 완료 안내

저장이 성공하면 안내 팝업에서 다음 내용을 확인합니다.
  - 저장한 버전
  - 저장 전 크기와 저장 후 크기
  - 저장된 DAT와 구조 파일 경로
  - 백업 DAT와 기존 구조 파일의 백업 경로

크기가 바뀌면 변경 전 헤더·Struct로 다시 열 수 없다는 안내가 나옵니다.
크기가 같아도 구조가 바뀌었으면 그 사실을 표시합니다.
값만 바뀐 경우에는 일반 저장 안내가 나옵니다.
확인은 이미 끝난 저장의 안내를 닫는 버튼입니다.
확인을 누르는 시점에 저장이 시작되는 것이 아닙니다.

12.4 수정한 DAT 다시 열기

  1) sample.dat와 sample.dat.schema.json을 같은 폴더에 둡니다.
  2) DAT Diff에서 원하는 버전의 DAT 경로를 지정합니다.
  3) 헤더 사용 (자동 구조 파일 대신)을 해제합니다.
  4) 한 파일이면 Load Only에서 Load, 두 파일이면 Load / 비교를 누릅니다.

구조 파일이 있으면 변경 전 헤더가 없거나 입력칸에 이전 헤더가 남아 있어도
현재 구조 파일로 열 수 있습니다. 헤더와 Struct를 비워도 됩니다.

DAT를 옮길 때는 구조 파일도 함께 옮깁니다.
DAT 이름을 newname.dat로 바꾸면 구조 파일도 newname.dat.schema.json으로 바꿉니다.
구조 파일의 별도 경로를 지정하는 기능은 없습니다.
구조 파일은 손으로 편집하지 말고 앱이 저장한 파일을 사용하세요.

구조 파일은 DAT 크기와 SHA-256 등으로 파일이 맞는지 검증합니다.
다른 DAT에 구조 파일을 임의로 붙이거나 DAT만 외부에서 수정하면
다시 열 때 검증 오류가 날 수 있습니다.

12.5 저장 실패와 백업 복구

백업 단계가 실패하면 원본을 바꾸지 않습니다.
파일 교체 중 오류가 나면 이전 DAT와 구조 파일 쌍으로 복구를 시도합니다.
저장 실패 상태가 표시되면 오류와 실제 파일을 확인한 뒤 다시 작업하세요.

로드 이후 다른 프로그램이 DAT를 바꾸었거나 다른 버전에서 같은 경로에
저장했다면 덮어쓰기를 막습니다. 다시 로드하여 최신 파일을 확인해야 합니다.
필요한 미저장 작업이 있다면 바로 재로드하지 말고 먼저 작업 내용을 확인하세요.

백업으로 과거 상태를 보려면 백업 DAT를 지정해서 로드할 수 있습니다.
같은 이름의 백업 구조 파일이 있으면 함께 두고, 없으면 당시의 헤더가 필요합니다.
원본 경로를 과거 상태로 되돌리려면 현재 파일을 별도로 보관한 뒤
백업 DAT와 그에 맞는 구조 파일을 원본 이름으로 함께 복사합니다.
구조 파일 없는 과거 백업에 현재 구조 파일을 섞어 두지 마세요.
이 복구용 파일 복사는 탐색기에서 수행하며 앱의 실행 취소와는 별개입니다.

구조 파일로 앱에서 다시 열린다는 사실이 대상 C/C++ 프로그램과의 호환성을
보장하는 것은 아닙니다. 대상 프로그램이 같은 구조와 크기를 기대하는지 확인하세요.
사용자 정의 크기 멤버나 체크섬은 앱이 자동 계산하지 않습니다.


13. 작업 전환과 전체 초기화

13.1 비교 표시 옵션을 바꿀 때

구조 비교 또는 차이점만 보기 옵션을 바꿀 때 미저장 변경이나 입력이 있으면
다음 선택 창이 나타납니다.

  저장 후 변경
    입력 초안을 먼저 적용·검증하고 변경된 버전을 모두 백업 저장합니다.
    저장과 검증이 성공하면 새 옵션으로 목록을 구성하고 편집 이력을 초기화합니다.

  저장하지 않고 변경
    양쪽 작업본을 각각 마지막 저장 상태로 되돌리고 새 옵션으로 목록을 만듭니다.
    파일을 디스크에 쓰지 않습니다. 미저장 변경과 입력 및 이력을 버립니다.
    한쪽만 저장한 상태라면 그쪽은 그 저장 상태로, 다른 쪽은 그쪽의 마지막
    저장 상태로 돌아갑니다.

  취소
    기존 표시 옵션과 목록, 입력, 편집 작업을 유지합니다.

입력 검증이나 저장이 실패하면 표시 옵션은 바뀌지 않습니다.
버전1만 저장에 성공한 뒤 버전2 저장이 실패했다면 버전1의 저장은 유지됩니다.
저장된 파일까지 자동으로 과거 상태로 되돌리는 동작은 하지 않습니다.

미저장 작업이 없으면 별도 저장 선택 없이 옵션을 바꿉니다.
옵션 전환에 성공하면 실행 취소·다시 실행 이력이 초기화됩니다.
현재 작업을 유지하려면 옵션을 바꾸기 전에 결과와 저장 상태를 확인하세요.

13.2 입력 변경과 모드 전환 및 재로드

DAT 경로, 헤더, Struct나 파싱 조건을 바꾸면 해당 설정으로 다시 로드해야 합니다.
기존 결과나 미저장 입력을 버리게 되는 경우 화면의 확인 메시지를 읽고 결정합니다.
Load Only 전환과 조회 대상 변경도 로드된 결과를 초기화할 수 있습니다.
비교 표시 옵션 전환의 세 가지 선택 창이 모든 전환에 공통으로 나오는 것은 아닙니다.

다시 Load하면 성공한 새 데이터로 결과와 편집 이력을 교체합니다.
재로드가 실패하거나 취소되면 기존 작업본을 유지합니다.
DAT 로드 중의 취소 버튼은 로드 작업을 취소하는 버튼입니다.
이미 적용한 편집을 되돌리려면 실행 취소를 사용합니다.

13.3 전체 초기화와 종료

DAT Diff의 전체 초기화는 확인 후 다음 내용을 지웁니다.
  - 양쪽 DAT 경로와 헤더 및 Struct
  - SCTC 경로 선택과 파싱 옵션
  - 로드된 결과, 미저장 편집과 입력
  - 실행 취소·다시 실행 이력
  - 비교 모드와 표시 옵션

DAT 화면은 Run Data, Pack 8, ASCII 등의 초기 상태로 돌아갑니다.
RealTime Viewer 설정은 유지되며 디스크의 DAT, 백업과 헤더는 삭제하지 않습니다.

앱 종료 시 미저장 DAT 작업이나 입력이 있으면 버릴지 확인합니다.
계속 사용하려면 종료를 취소하고 입력을 정리한 뒤 필요한 버전을 저장하세요.
자동 저장에 의존하지 말고 종료 전에 각 버전의 미저장 표시를 확인합니다.

15. 샘플로 연습하기

소스 저장소에 TestHeaders/DatDiff 샘플이 있는 경우 아래 순서로 연습합니다.
배포 파일만 받은 경우 샘플이 포함되어 있지 않을 수 있습니다.
저장 연습 전에 샘플을 별도의 작업 폴더에 복사합니다.

15.1 기본 비교와 양방향 적용

  버전1: version1.h / version1.dat / Struct DemoV1
  버전2: version2.h / version2.dat / Struct DemoV2

  1) DAT Diff에서 Load Only와 양쪽 Use SCTC Path를 해제합니다.
  2) 각 버전의 헤더, DAT, Struct를 위 조합으로 입력합니다.
  3) 처음 샘플을 열 때는 Pack 8과 ASCII를 사용합니다.
  4) Load / 비교를 누르고 차이점만 보기를 체크합니다.
  5) legacy 행에서 →를 눌러 버전2에 추가되는지 확인합니다.
  6) 실행 취소를 누른 뒤 같은 행에서 ←를 눌러 버전1에서 삭제되는지 확인합니다.
  7) 실행 취소로 다시 복원하고 conflict 행의 값 적용을 연습합니다.
  8) 루트 행 적용과 개별 멤버 적용의 범위가 다른지 확인합니다.

15.2 저장과 구조 파일 재로드

  1) 복사본에서 한쪽에 구조 변경을 적용합니다.
  2) 변경한 버전만 저장합니다.
  3) 저장 안내의 크기, 백업과 구조 파일 경로를 확인합니다.
  4) 미저장인 다른 쪽 작업이 있다면 저장할지 결정합니다.
  5) Load Only로 전환하고 저장한 버전을 조회 대상으로 선택합니다.
  6) 해당 버전의 헤더와 Struct를 비우고 저장한 DAT 경로를 지정합니다.
  7) 헤더 사용 (자동 구조 파일 대신)을 해제하고 Load를 누릅니다.
  8) 생성된 구조 파일로 변경된 구조가 다시 열리는지 확인합니다.

다른 샘플
  array_members.h와 array_members_v1.dat / array_members_v2.dat
    중첩 구조체 배열의 개별 멤버 적용과 직접 값 편집을 연습합니다.
  structure_v1.h / structure_v1.dat와 structure_v2.h / structure_v2.dat
    pack, 멤버 순서, 배열 길이 차이와 그룹 전체 적용을 확인합니다.

실시간 트리 구조를 연습하려면 test_sample.h나 TestHeaders/test_shm.h를 등록합니다.
헤더만으로 실제 SHM 값이 생기는 것은 아니므로 Run에는 대응하는 SHM이 필요합니다.


16. 오류 해결과 지원 범위

16.1 자주 겪는 문제

  프로그램이 실행되지 않음
    Windows x64용 .NET 8 Desktop Runtime 설치를 확인합니다.
    .NET 8 런타임 안내가 나오면 Desktop Runtime 종류인지 확인하세요.
    배포 압축을 완전히 풀고 실행하세요.

  먼저 헤더 파일을 파싱하세요 / 구조체 미발견
    헤더 분석이 끝났는지 확인합니다.
    Struct에는 파일 이름이 아닌 실제 구조체 이름을 입력합니다.
    해당 구조체를 정의한 헤더가 등록되어 있는지 확인합니다.

  미해결 타입 / 미발견 타입
    자세히 보기 또는 미발견 타입 보기에서 필요한 정의를 확인합니다.
    관련 헤더를 추가하고 다시 분석합니다.
    DAT에서는 include 순서, 추가 include 경로와 매크로 조건도 확인합니다.

  헤더 파일 누락
    표시된 전체 경로에 파일이 있는지 확인합니다.
    Use SCTC와 Use SCTC Path는 지정된 기본 경로를 사용하므로
    설치 위치가 다르면 실제 파일을 직접 등록합니다.

  헤더 Refresh나 삭제가 비활성 상태
    실행 중인 모든 SHM 탭을 Stop으로 중지합니다.
    헤더 분석이나 트리 생성 중이라면 완료될 때까지 기다립니다.

  Load 후 실시간 값이 안 보임
    Load는 탭과 구조만 준비합니다. 해당 탭의 Run을 누릅니다.
    대상 프로그램 실행과 SHM Name을 확인합니다.

  SHM 연결 실패 또는 갱신 실패
    대상 프로그램이 해당 공유 메모리를 생성했는지 확인합니다.
    SHM 이름, 접근 권한, 대상 프로세스 상태와 구조체 크기를 확인합니다.
    마지막 갱신 시각을 보고 표시 값이 최신인지 확인합니다.

  값이 이상하거나 오프셋이 맞지 않음
    실제 데이터를 기록한 버전의 헤더와 Struct인지 확인합니다.
    Windows x64 배치, pack과 매크로 조건 및 대상 구조체 크기를 확인합니다.
    C/C++에서 sizeof로 얻은 크기와 화면의 Total Size를 비교하면 도움이 됩니다.

  검색 결과가 없거나 VALUE가 비어 있음
    헤더 분석과 SHM 탭의 트리 생성이 완료되었는지 확인합니다.
    이름 또는 타입의 일부를 검색하고 검색 범위를 확인합니다.
    검색 결과 VALUE 대신 더블클릭해서 이동한 트리의 값을 확인합니다.

  DAT 크기와 Struct 크기가 다름
    선택한 DAT 버전과 헤더·Struct의 조합을 확인합니다.
    파싱 옵션과 배열 길이에 영향을 주는 매크로를 확인합니다.
    구조 변경 후 저장한 DAT라면 생성된 구조 파일을 함께 두고 자동 로드합니다.
    파일 머리말·꼬리말이나 여러 레코드가 들어 있는 파일은 지원 대상이 아닙니다.

  구조 파일 검증 실패
    DAT와 구조 파일이 같은 저장 결과의 쌍인지 확인합니다.
    파일 이동·이름 변경 후에도 두 이름이 정확히 대응하는지 확인합니다.
    현재 DAT에 맞는 헤더가 있다면 헤더 사용을 명시적으로 선택할 수 있습니다.

  한글 깨짐 또는 문자열 입력 거부
    DAT의 문자 인코딩을 확인하고 ASCII / CP949 / UTF-8을 맞춥니다.
    배열의 바이트 용량과 NUL 공간을 확인합니다.
    문자가 선택한 인코딩으로 표현되지 않으면 다른 인코딩이나 입력을 검토합니다.

  적용한 행이 목록에서 사라지지 않음
    연속 작업을 위해 기존 행을 유지하는 정상 동작입니다.
    중앙의 현재 상태와 남은 차이 개수를 확인합니다.
    목록을 새로 만들려면 작업을 정리한 뒤 표시 옵션을 바꾸거나 재로드합니다.

  저장 버튼이 비활성 상태
    로드가 끝났는지 확인합니다.
    셀 입력과 고급 편집 입력을 적용하거나 취소하고 표시된 오류를 해결합니다.

  저장 실패 또는 다른 프로그램이 파일을 변경했다는 안내
    DAT 폴더의 쓰기 권한과 파일 사용 상태를 확인합니다.
    외부 변경 감지 시 작업 내용을 확인한 뒤 최신 파일을 다시 로드합니다.
    버전1과 버전2가 같은 DAT 경로인지도 확인합니다.

  설정 저장 실패
    ShmViewer.exe 폴더에 쓰기 권한이 있는지 확인합니다.
    실시간 설정은 실행 파일 옆에 저장됩니다.

16.2 지원 범위

DAT는 Windows C++ x64 little-endian 구조체 하나를 그대로 저장한 파일을 대상으로 합니다.
예를 들어 fwrite로 구조체 하나를 기록한 파일입니다.
확장자가 .dat인 모든 파일 형식을 읽는 범용 뷰어는 아닙니다.

지원되는 주요 데이터
  기본 정수와 실수, bool, enum, 구조체, union, 배열, 중첩 구조체와 비트필드,
  char 문자열과 wchar 배열, 포인터 주소값.

다음 범위는 지원하지 않거나 사용자가 별도로 확인해야 합니다.
  - 32비트 구조체, 다른 CPU 바이트 순서, 파일 머리말·꼬리말, 연속 레코드
  - 포인터가 가리키는 외부 메모리나 파일의 자동 추적
  - 사용자 정의 크기 멤버와 체크섬의 자동 갱신
  - 임의의 다른 이름을 가진 멤버 사이의 수동 경로 연결

비교에서 구조체의 일반 패딩 바이트 차이는 제외합니다.
union 원시 바이트와 문자열의 NUL 뒤 바이트 차이는 표시할 수 있습니다.
따라서 표시된 문자열이 같아도 뒤쪽 바이트 때문에 차이가 있을 수 있습니다.

실시간 SHM 조회는 한 시점의 바이트를 읽는 방식입니다.
대상 프로그램의 쓰기 작업을 정지시키거나 여러 필드의 일관성을 보장하지 않습니다.
동작 판단에 사용할 때는 대상 프로그램의 상태와 갱신 시각을 함께 확인하세요.

문제가 반복되면 오류 메시지, 사용한 Struct, 예상 크기, 실제 파일 크기,
헤더·DAT 버전과 적용한 파싱 옵션을 정리하면 원인을 확인하는 데 도움이 됩니다.
