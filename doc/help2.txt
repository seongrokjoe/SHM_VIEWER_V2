SHM VIEWER 핵심 사용법

1. 헤더 / Struct / 데이터 매핑

헤더(.h/.hpp)는 데이터의 구조를 정의하고, Struct는 그중 사용할 구조체 이름입니다.
앱은 Struct의 멤버 타입·크기·오프셋에 따라 SHM 또는 DAT의 바이트를 값으로 읽습니다.

  예: 헤더에 struct Demo { int count; float temp; };가 정의된 경우
      Struct 입력: Demo
      count: 시작 위치 0, 크기 4바이트 / temp: 시작 위치 4, 크기 4바이트
      대응하는 데이터 크기: 8바이트

Struct에는 헤더 파일명이 아닌 구조체 이름을 입력합니다.
중첩 구조체나 enum을 참조하면 그 정의가 있는 헤더도 함께 등록합니다.
데이터를 만든 버전의 헤더와 Pack·매크로 조건이 맞아야 값이 정확합니다.

  SHM 매핑: SHM Name으로 메모리를 찾고, Struct로 내용을 해석합니다.
  DAT 매핑: DAT 경로로 파일을 찾고, 해당 버전의 Struct로 내용을 해석합니다.
            헤더로 로드할 때 DAT 크기는 Struct 크기와 정확히 같아야 합니다.

DAT와 같은 폴더에 '<DAT 파일명>.schema.json'이 있으면 그 구조 파일을 우선 사용합니다.
예: sample.dat → sample.dat.schema.json.
이때는 DAT 경로만 지정하면 되며 헤더·Struct 입력은 사용하지 않습니다.
헤더로 열려면 '헤더 사용 (자동 구조 파일 대신)'을 체크합니다.


2. RealTime Viewer 실시간 조회

  1) '+ 파일 추가'로 헤더를 등록하고 분석 완료를 기다립니다.
  2) SHM Name과 Struct를 입력하고 Refresh 주기를 선택합니다.
  3) Load로 탭과 트리를 준비하고 Total Size가 대상 구조체 크기와 맞는지 확인합니다.
  4) 해당 탭에서 Run을 눌러 실제 값을 읽습니다. 대상 프로그램이 SHM을 생성해야 합니다.
  5) TYPE 옆 버튼으로 트리를 펼칩니다. Stop은 갱신 중지, 탭의 ✕는 탭 닫기입니다.

  - 헤더 영역 Refresh: 헤더를 다시 분석합니다. 모든 SHM 탭을 Stop한 뒤 사용합니다.
  - 탭 안 Refresh: 수동 모드에서 Run 후 현재 값을 한 번 읽습니다.
  - 검색: 이름·타입을 검색하고 결과를 더블클릭하면 해당 항목으로 이동합니다.
  - 우클릭: TYPE/NAME은 복사, 일반 VALUE는 Run 중 '바이너리 확인'을 사용합니다.
  - Use SCTC: 기본 헤더와 SHM 탭을 설정합니다. 연결은 각 탭에서 Run을 눌러 시작합니다.


3. DAT 조회와 비교

파일 하나 조회
  Load Only 체크 → 조회 대상 버전 선택 → DAT와 구조 정보 지정 → Load.
  구조 파일이 없으면 해당 쪽의 '+ 헤더'와 Struct를 지정합니다.

두 파일 비교
  Load Only 해제 → 버전1·버전2에 DAT와 구조 정보 각각 지정 → Load / 비교.
  왼쪽은 버전1, 오른쪽은 버전2입니다. 각 DAT에 맞는 헤더·Struct를 따로 사용합니다.
  멤버 경로로 자동 대응하며 배열은 현재 인덱스 기준으로 비교합니다.

  - 구조 비교: 멤버 유무·타입·배치·배열 길이 등 구조 차이를 표시합니다.
  - 차이점만 보기: 구조 또는 값이 다른 항목을 표시합니다.
  - 둘 다 해제: 전체 항목을 표시합니다. 두 옵션은 동시에 켜지지 않습니다.
  - 이전 차이 / 다음 차이: 현재 남아 있는 차이로 이동합니다.
  - Use SCTC Path: 체크한 쪽에 Run Data / Init Data 기본 경로와 Struct를 입력합니다.


4. DAT 적용과 값 편집

  →: 버전1의 현재 내용을 버전2에 적용합니다.
  ←: 버전2의 현재 내용을 버전1에 적용합니다.

소스에만 있는 항목은 대상에 추가합니다. 소스에 없는 항목은 대상에서 삭제합니다.
예: 왼쪽에만 legacy가 있으면 →는 오른쪽에 추가, ←는 왼쪽에서 삭제합니다.
그룹 행을 적용하면 하위 구조와 값을 함께 맞춥니다. 한 값만 바꾸려면 해당 멤버를 선택합니다.
배열·union 때문에 적용 범위가 넓어지면 안내된 그룹을 확인한 뒤 적용합니다.
Ctrl/Shift로 여러 행을 선택하고 상단의 방향 적용 버튼으로 일괄 적용할 수 있습니다.

값 셀 더블클릭 또는 F2 → 입력 → Enter로 적용, Esc로 입력 취소.
입력 예: 123 / 0x7B / 3.14 / enum 이름 / "hello" / hex:00112233.
문자열은 파일에 맞는 ASCII·CP949·UTF-8을 선택합니다. HEX는 바이트 표시입니다.
고급 편집의 '0 적용'과 '선택 항목 삭제'는 표시된 편집 대상 버전에 반영됩니다.
실행 취소 / 다시 실행으로 작업을 되돌리거나 복원합니다.
Load Only에서는 값만 편집하며 구조와 파일 크기를 유지합니다.


5. 저장과 다시 열기

편집·좌우 적용은 앱 안의 작업본을 바꿉니다. 저장해야 디스크 DAT가 바뀝니다.
'버전1 저장' / '버전2 저장'은 해당 쪽만 저장합니다.
Load Only에서는 'DAT 저장 · 원본 백업'을 사용합니다.

저장 시 원래 DAT 경로를 갱신하고 저장 전 파일을 날짜·시간 이름으로 백업합니다.
현재 구조 파일도 생성합니다. 예: sample.dat + sample.dat.schema.json.
다시 열 때는 이 두 파일을 같은 폴더에 두고 DAT만 지정하면 됩니다.
이름을 바꾸거나 이동할 때도 두 파일을 함께 처리합니다. 원본 헤더는 수정되지 않습니다.

적용 후 같아진 행도 목록에 남습니다. 남은 차이는 중앙 상태와 차이 이동으로 확인합니다.
표시 옵션을 바꿀 때 미저장 작업이 있으면 저장 후 변경 / 저장하지 않고 변경 / 취소를 선택합니다.
저장하지 않고 변경하면 각 버전의 마지막 저장 상태로 돌아갑니다.
재로드·모드 변경·전체 초기화·종료 전에는 필요한 변경을 저장하세요.
