SCTC_CONFIG.exe 사용 방법
========================================

1. 프로그램의 용도

SCTC 설정 폴더의 CSV 또는 XML 파일을 불러와 다음 항목을 편집합니다.

    Main / SCD / UI : 화면에 표시되는 true/false 설정
    Driver          : NeedLoad와 Arg1~Arg5
    Function        : 파일별 시뮬레이션 설정
    Alarm           : 파일별 DisplayOnly 적용과 대상 StopMode 선택

CSV Alarm 화면의 Export에서는 StopMode_Run과 StopMode_Default가 다른 행을
CSV 보고서로 내보낼 수 있습니다.

화면에서 값을 바꾼 뒤 Save를 눌러야 설정 파일에 반영됩니다.
Save는 현재 선택한 탭의 설정을 해당 설정 파일에 직접 저장합니다.


2. 실행 환경과 폴더 준비

(1) SCTC_CONFIG.exe를 더블클릭합니다.
    현재 프로젝트의 기본 배포 방식은 Windows 64비트용입니다.
    이 방식의 실행 파일에는 .NET 8 Windows Desktop Runtime(x64)이 필요합니다.
    실행 PC에는 프로그램 실행을 위한 Visual Studio 설치가 필요하지 않습니다.

(2) 편집할 설정 루트 폴더를 준비합니다.
    Path에는 General.csv 또는 SCTC.xml이 들어 있는 폴더를 지정합니다.
    Driver / Function / Alarm 폴더는 그 아래에 있어야 합니다.

CSV 탭에서 읽는 구조:

    설정루트\
        General.csv                 [필수]
        SCD\
            SCDGeneral.csv          [필수]
        CTC_UI.xml                  [선택]
        Driver\
            Driver.csv              [선택]
        Function\
            *.csv                   [선택]
        Alarm\
            *.csv                   [선택]

XML 탭에서 읽는 구조:

    설정루트\
        SCTC.xml                    [필수]
        SCD.xml                     [필수]
        CTC_UI.xml                  [선택]
        Driver\
            Driver.xml              [선택]
        Function\
            *.xml                   [선택]
        Alarm\
            *.xml                   [선택]

Function과 Alarm은 해당 폴더에 바로 들어 있는 파일을 읽습니다.
그 아래 하위 폴더를 재귀적으로 검색하지 않습니다.
선택 파일이나 폴더가 없으면 해당 영역은 비어 있을 수 있습니다.

CSV Function에서는 파일명에 Def 또는 IOInfo가 포함된 파일을 제외합니다.
이 이름 필터는 XML Function에는 적용되지 않습니다.


3. 기본 작업 순서

(1) 상단 Path에 실제 설정 폴더 경로를 입력합니다.
    Browse를 누르면 폴더 선택 창에서 선택할 수 있습니다.
    처음 표시되는 Path는 기본값이므로 작업 대상 폴더로 확인·변경합니다.

(2) 작업할 CSV 또는 XML 탭을 선택합니다.

(3) Load를 눌러 선택한 탭의 파일을 읽습니다.
    Browse와 탭 선택만으로 파일이 자동으로 로드되지는 않습니다.
    CSV와 XML은 각각 탭을 선택한 상태에서 Load해야 합니다.

(4) Main/SCD/UI, Driver, Function, Alarm에서 필요한 설정을 변경합니다.

(5) 저장할 탭이 선택되어 있는지 확인하고 상단 Save를 누릅니다.

(6) 저장 설정 창에서 백업 여부와 백업 폴더명을 지정한 뒤 저장을 누릅니다.
    백업 방법은 9번 항목을 참고합니다.

(7) "저장이 완료되었습니다." 메시지를 확인합니다.
    같은 탭에서 Load를 눌러 저장한 파일을 다시 읽고 결과를 확인합니다.

Load는 선택한 탭의 화면 내용을 파일에서 다시 읽어 교체합니다.
저장하지 않은 편집은 해당 탭을 다시 Load하거나 프로그램을 종료하면 사라집니다.
저장 설정 창의 취소는 저장을 취소하며, 화면의 편집값은 유지합니다.

폴더를 바꿀 때는 새 Path를 지정한 뒤 작업할 탭에서 다시 Load합니다.
로드 후 Path만 바꾸고 Save하는 사용은 피하고, 한 번에 하나의 설정 폴더를 대상으로
Load → 편집 → Save 순서로 작업합니다.

저장 후 계속 편집할 때는 해당 탭에서 다시 Load하여 저장된 내용을 기준으로 작업합니다.
특히 CSV Alarm에서 Run을 저장한 뒤 Setup 등 다른 모드를 추가로 변경하려면
먼저 다시 Load합니다. 다시 읽지 않고 연속 저장하면 Load 당시의 내용으로
이전에 저장한 변경을 되돌릴 수 있습니다.
Export 보고서가 Alarm 폴더에 있으면 다시 Load하기 전에 다른 폴더로 옮깁니다.


4. 화면 구성과 공통 조작

상단 버튼:

    Path   : 설정 루트 폴더 경로
    Browse : 폴더 선택
    Load   : 선택한 CSV/XML 탭의 파일 읽기
    Save   : 선택한 CSV/XML 탭의 설정 저장

각 탭의 화면은 왼쪽부터 Main/SCD/UI, Driver, Function, Alarm 순서입니다.
영역 사이의 세로 경계선을 드래그하면 폭을 조절할 수 있습니다.
목록이 길면 각 영역의 스크롤을 사용합니다.

true/false 토글은 클릭하여 상태를 전환합니다.
TRUE 또는 true는 켜짐, FALSE 또는 false는 꺼짐을 나타냅니다.
현재 상태는 토글에 표시된 값으로 확인합니다.

CSV 탭과 XML 탭은 각각 별도의 로드 상태와 편집값을 가지고 있습니다.
Save는 두 탭을 한 번에 저장하지 않습니다.
아직 정상적으로 Load하지 않은 탭에서는 Save를 사용할 수 없습니다.


5. Main / SCD / UI 설정

각 항목 오른쪽의 토글로 값을 바꾸고 Save합니다.
설정 파일에 해당 키나 요소가 존재할 때 화면에 표시됩니다.
항목이 보이지 않으면 대상 파일과 해당 키의 존재 여부를 확인합니다.

CSV Main: General.csv
    UseStandaloneMode
    UseVirtualDriver
    UseVirtualInterlock
    UseFunctionSimulationMode

XML Main: SCTC.xml
    UseStandaloneMode
    UseVirtualDriver

CSV SCD: SCD\SCDGeneral.csv
    SimulationSCD
    SimulationFunction
    SimulationDriver

XML SCD: SCD.xml
    SimulationSCD
    SimulationSCDforEC
    SimulationFunction
    SimulationDriver

UI: CTC_UI.xml
    EnableUIDebugMode

CTC_UI.xml은 CSV와 XML 탭에서 같은 파일을 편집합니다.
파일이 없거나 EnableUIDebugMode의 true/false 값을 찾지 못하면 UI 목록이 비어 있습니다.
한 탭에서 UI 설정을 저장한 뒤 다른 탭으로 작업하려면 그 탭을 다시 Load하여
최신 CTC_UI.xml 상태를 확인합니다.


6. Driver 설정

각 드라이버의 이름과 파일명을 확인한 뒤 다음 항목을 편집합니다.

    NeedLoad : true/false 토글
    Args     : 왼쪽부터 Arg1, Arg2, Arg3, Arg4, Arg5 텍스트 입력칸

이름과 파일명은 확인용으로 표시되며 입력칸으로 편집하는 항목은 아닙니다.
NeedLoad 또는 Args를 변경한 뒤 Save하면 해당 드라이버 설정에 반영됩니다.
Args에는 해당 드라이버에서 사용하는 값과 형식에 맞게 입력합니다.
CSV Driver는 Args의 쉼표를 자동으로 감싸거나 이스케이프하지 않습니다.
CSV Args에 쉼표를 입력하면 컬럼 구조가 달라질 수 있으므로 쉼표를 입력하지 않습니다.

XML Driver에서 회색으로 비활성화된 항목은 원본 XML에 해당 요소가 없는 경우입니다.
이 화면은 없는 NeedLoad나 Arg 요소를 새로 추가하지 않습니다.


7. Function 시뮬레이션 설정

Function 목록에는 파일명과 시뮬레이션 상태 토글이 표시됩니다.
토글을 바꾼 뒤 Save하면 그 파일의 대상 항목 전체에 같은 상태를 적용합니다.

    CSV: 각 대상 데이터 행의 7번째 컬럼을 TRUE 또는 FALSE로 적용
    XML: 파일 안의 IsSimulation 요소들을 true 또는 false로 적용

토글을 조작한 파일이 저장 대상이 됩니다.
목록에 파일이 있어도 토글을 조작하지 않았다면 해당 Function 파일은 저장하지 않습니다.

경고 아이콘이 표시되는 경우:

    파일 안의 시뮬레이션 값이 서로 통일되지 않은 경우입니다.
    이런 파일을 처음 변경하면 다음 확인 창이 표시됩니다.
    "이 파일의 시뮬레이션 설정이 통일되지 않았습니다. 변경하시겠습니까?"

    예(Yes): 표시된 토글 상태를 반대로 바꾸며, Save 시 대상 항목 전체를 그 값으로 통일합니다.
    아니오(No): 상태를 바꾸지 않고 현재 설정을 유지합니다.

파일 전체에 적용되는 기능이므로 개별 행이나 개별 IsSimulation의 서로 다른 값을
유지할 필요가 있으면 해당 파일의 토글을 조작하지 않습니다.


8. Alarm의 DisplayOnly 적용

Alarm 파일마다 오른쪽에 DisplayOnly 체크박스가 있습니다.
상단 Run / Setup / Default 체크박스는 저장 시 바꿀 StopMode를 지정합니다.

    Run     → StopMode_Run
    Setup   → StopMode_Setup
    Default → StopMode_Default

Load 직후 상단 Run / Setup / Default는 모두 선택되어 있습니다.
상단 선택은 DisplayOnly가 체크된 모든 Alarm 파일에 공통으로 적용됩니다.

적용 순서:

    (1) 적용할 모드의 상단 체크박스만 선택합니다.
    (2) 대상 파일의 DisplayOnly를 체크합니다.
    (3) Save를 누릅니다.

선택한 파일의 모든 대상 알람에 대해 선택한 StopMode를 DisplayOnly:1로 바꿉니다.
상단에서 선택하지 않은 모드는 그대로 유지합니다.
상단 모드를 모두 해제하면 Alarm 변경을 적용하지 않습니다.
파일의 DisplayOnly가 해제되어 있으면 그 파일의 Alarm 변경을 적용하지 않습니다.

예: BM.csv의 Run만 DisplayOnly로 적용

    Run = 체크, Setup = 해제, Default = 해제
    BM.csv의 DisplayOnly = 체크
    CSV 탭에서 Save

    결과: BM.csv의 대상 행 전체에서 StopMode_Run만 DisplayOnly:1로 변경

CSV Alarm의 StopMode 위치는 8번째(Run), 9번째(Setup), 10번째(Default) 컬럼입니다.
XML Alarm에서는 해당 이름의 기존 요소들을 변경합니다.

파일의 DisplayOnly 체크는 로드 시 해당 파일의 세 모드 값을 보고 초기화됩니다.
해제 상태는 모든 값이 DisplayOnly가 아니라는 뜻일 수 있으며, 일부 행이나 모드에는
이미 DisplayOnly:1이 들어 있을 수 있습니다.

DisplayOnly 해제는 앞으로의 적용을 건너뛰는 동작입니다.
이미 저장한 DisplayOnly:1을 원래 StopMode로 자동 복원하지 않습니다.
복원이 필요하면 백업 파일의 원래 값을 사용한 후 다시 Load합니다.


9. Save와 백업

Save를 누르면 "저장 설정" 창이 열립니다.
기본값은 "백업하지 않음"이 체크된 상태입니다.
백업을 남기려면 이 체크를 해제하고 백업 폴더명을 확인합니다.

백업 사용 순서:

    (1) "백업하지 않음" 체크를 해제합니다.
    (2) 활성화된 "백업 폴더명" 입력칸에 폴더 이름을 지정합니다.
        기본 이름: 원본폴더명_yyyyMMddHHmm
        폴더명에는 저장할 전체 경로 대신 새 백업 폴더 이름을 입력합니다.
    (3) 저장을 누릅니다.

백업은 Path 폴더의 상위 폴더에 생성되며,
현재 디스크에 있는 설정 폴더 전체를 하위 폴더까지 복사합니다.
선택한 탭의 파일뿐 아니라 원본 폴더 안의 CSV와 XML 등 전체 파일이 포함됩니다.
백업 복사가 끝난 뒤 선택한 탭을 저장합니다.

예시:
    Path: D:\SCTC\dat\clean_csv
    백업 폴더명: clean_csv_202610141530
    백업 위치: D:\SCTC\dat\clean_csv_202610141530
    실제 저장 위치: 원래 D:\SCTC\dat\clean_csv 아래의 설정 파일

백업 이름이 기존 폴더와 같으면 같은 이름의 파일을 덮어쓸 수 있습니다.
각 저장의 백업을 따로 보관하려면 기존에 없는 폴더명을 지정합니다.
백업을 사용할 때 백업 폴더명이 비어 있지 않은지도 확인합니다.
이름이 비어 있으면 "백업하지 않음"을 해제해도 백업을 만들지 않고 저장합니다.

"백업하지 않음"을 선택하면 백업 없이 원본 설정 파일을 저장합니다.
Save는 새 결과 폴더를 만드는 기능이 아니라 원본 설정 파일을 갱신하는 기능입니다.

"저장이 완료되었습니다." 메시지를 확인한 뒤 변경 파일을 확인합니다.
저장 중 오류가 발생하면 일부 파일이 이미 저장되었을 수 있으므로
오류 메시지와 대상 파일, 생성된 백업을 확인합니다.

저장 전 상태로 되돌리려면 프로그램을 종료하고 필요한 원본 파일을 백업본으로 복원한 뒤,
다시 실행하여 해당 탭에서 Load합니다.


10. CSV Alarm Export 사용법

Export 버튼은 CSV 탭의 Alarm 영역에 있습니다.
불러온 각 Alarm CSV의 StopMode_Run과 StopMode_Default가 다른 행을 내보냅니다.
비교할 때 양쪽 값의 앞뒤 공백을 제거합니다. Setup은 비교 대상에 포함하지 않습니다.

사용 순서:

    (1) CSV 탭에서 대상 설정 폴더를 Load합니다.
    (2) Alarm 영역의 Export를 누릅니다.
    (3) 완료 메시지의 파일 경로와 차이 개수를 확인합니다.
    (4) 생성된 CSV 보고서를 열어 차이 행을 확인합니다.

저장 위치:
    로드한 설정 폴더의 Alarm 폴더

파일 이름:
    yyyyMMdd_HHmmss.csv
    이름이 같으면 _1, _2 등의 접미사를 붙여 기존 보고서와 구분합니다.

보고서 컬럼:
    File, AlarmID, Line, StopMode_Run, StopMode_Default, KName

    File  : 원본 Alarm CSV 파일명
    AlarmID: 첫 번째 컬럼의 알람 ID
    Line  : 주석과 빈 줄을 포함한 1부터 시작하는 원본 행 번호
    KName : 두 번째 컬럼의 알람 이름

차이가 없으면 헤더만 있는 CSV를 생성하고 차이 개수를 0으로 표시합니다.
보고서 인코딩은 BOM 없는 UTF-8입니다.

Export가 보는 값은 Load 당시 읽어 둔 Alarm CSV 내용입니다.
화면에서 체크한 DisplayOnly 적용 예정값으로 보고서를 만들지 않습니다.
Save 후의 최신 파일을 내보내는 순서:

    (1) CSV 탭에서 Save하여 변경을 저장합니다.
    (2) Alarm 폴더에 이전 Export 보고서가 있으면 다른 폴더로 옮깁니다.
    (3) CSV 탭에서 다시 Load합니다.
    (4) Export를 누르고 생성된 보고서를 확인합니다.
    (5) 새 보고서도 다음 Load 전에 Alarm 폴더 밖으로 옮겨 보관합니다.

내보낸 보고서는 다음 Load 전에 Alarm 폴더 밖의 별도 보관 폴더로 옮깁니다.
현재 Load는 Alarm 폴더의 모든 *.csv를 읽으므로 보고서를 그대로 남기면
6개 컬럼의 보고서를 Alarm 설정 파일로 읽으려 하여 로드 오류가 발생할 수 있습니다.


11. 작업 중 확인할 사항과 오류 대응

필수 파일을 찾을 수 없다는 로드 오류:
    Path가 설정 루트 폴더인지 확인합니다.
    CSV는 General.csv와 SCD\SCDGeneral.csv,
    XML은 SCTC.xml과 SCD.xml이 필요합니다.

화면의 항목이 비어 있음:
    선택한 탭에서 Load했는지 확인합니다.
    선택 파일이 존재하는지, 편집 대상 키나 요소가 파일에 들어 있는지 확인합니다.
    Function CSV의 Def/IOInfo 파일명 제외 규칙도 확인합니다.

Save가 비활성화되어 있음:
    현재 선택한 탭을 정상적으로 Load했는지 확인합니다.
    CSV를 불러왔다고 XML 탭에서도 바로 Save할 수 있는 것은 아닙니다.

Function의 경고 아이콘:
    파일 내 시뮬레이션 값이 혼합되어 있다는 뜻입니다.
    7번의 전체 적용 방식과 확인 창 동작을 확인합니다.

Alarm 변경이 적용되지 않음:
    해당 탭에서 파일의 DisplayOnly가 체크되어 있는지 확인합니다.
    상단 Run/Setup/Default 중 적용할 모드가 선택되어 있는지 확인합니다.
    화면 변경 후 Save했는지도 확인합니다.

Alarm CSV 로드 또는 저장 오류:
    메시지에 표시된 파일명과 행 번호를 확인합니다.
    헤더에는 최소 10개 컬럼이 필요하며 StopMode 컬럼 위치가 맞아야 합니다.
    Alarm 폴더에 Export 보고서가 남아 있다면 다른 폴더로 옮기고 다시 Load합니다.

XML 로드 오류:
    메시지의 파일 경로, 행과 위치를 확인하여 XML 문법을 점검합니다.

Export 오류:
    로드한 Alarm CSV가 있는지와 Alarm 폴더의 쓰기 권한을 확인합니다.

저장 오류:
    설정 폴더와 백업을 만들 상위 폴더의 쓰기 권한,
    디스크 여유 공간 및 다른 프로그램의 파일 잠금을 확인합니다.

파일을 외부 프로그램에서 수정한 경우:
    현재 화면은 Load 당시의 내용을 기준으로 편집합니다.
    새 파일 내용으로 작업하려면 저장하지 않은 편집 처리 여부를 결정한 뒤 다시 Load합니다.

문자 인코딩과 서식:
    파일을 읽을 때 BOM으로 인코딩을 감지하고, 감지한 인코딩으로 저장합니다.
    BOM이 없는 파일의 기본 읽기 인코딩은 UTF-8이며 CP949 자동 판별 기능은 없습니다.
    한글이 깨져 보이면 저장 전에 입력 인코딩을 확인합니다.
    CSV 줄바꿈은 처음 감지한 형식을 기준으로 저장하므로 혼합 줄바꿈은 통일될 수 있습니다.
    XML은 저장 과정에서 문서가 다시 기록되므로 저장 후 내용과 서식도 확인합니다.


12. 작업 예시

CSV 설정과 Alarm Run을 변경하고 백업 저장하기:

    1) Browse에서 General.csv가 있는 설정 루트 폴더 선택
    2) CSV 탭 선택 후 Load
    3) Main의 필요한 토글 변경
    4) Driver의 필요한 NeedLoad / Args 변경
    5) 필요한 Function 파일의 시뮬레이션 토글 변경
    6) Alarm 상단에서 Run만 선택하고 대상 파일의 DisplayOnly 체크
    7) CSV 탭이 선택된 상태에서 Save
    8) "백업하지 않음" 해제, 새 백업 폴더명 확인, 저장
    9) 완료 메시지와 실제 설정 파일·백업 폴더 확인

XML 설정을 변경하려면 같은 순서에서 XML 탭을 선택하고,
SCTC.xml 및 SCD.xml이 있는 설정 루트 폴더를 Load합니다.
